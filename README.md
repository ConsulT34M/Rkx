# RKX 디지털 자산 컨설팅 웹앱

HTML·CSS·JavaScript, Node.js/Express, MySQL 8로 만든 로컬 실행 프로젝트입니다. 거래소형 시세 화면과 상담 연결을 제공하며, **매매·입출금·자산 수탁 기능은 없습니다.**

## 화면과 권한

| 기능 | 동작 |
| --- | --- |
| 회원가입·본인확인 | 첫 화면에서 이름·이메일·비밀번호와 필수 동의를 입력하면 임시 가입 신청만 저장됩니다. 이어 왼쪽 화면에서 가상 인물의 이름·13자리 가상번호·연락처를 입력하고, 오른쪽 휴대전화 화면의 안내를 따라 IJ-info 문자 수신함에서 인증번호를 확인합니다. 신분증과 셀카 단계를 모두 마친 뒤에야 계정과 로그인 세션을 만듭니다. `samples/people.json`의 가상 인물 10명 중 정상 상태인 인물을 사용하며 결과는 `demo_verified`입니다. 현재는 **실습용 모의 판정**이며 실제 신원 확인이 아닙니다. |
| 로그인·로그아웃 | 이메일(아이디)과 비밀번호를 서버에서 검증하고 HttpOnly 세션을 발급·종료합니다. 서버 세션은 마지막 인증 요청 이후 30분이 지나면 만료됩니다. 로그인 2회 실패 후부터 CERN captcha-api 이미지 문자를 확인합니다. |
| 상담 접수 | 고객이 문의 유형과 내용을 입력하면 접수번호를 만듭니다. 같은 요청 ID를 다시 보내면 기존 접수번호를 반환합니다. 말결로 보내는 정보는 상담용 고객 식별키, 문의 유형·내용, 접수번호로 제한하며 전화 콜백일 때만 연락처·희망 시간·녹취 동의 상태가 추가됩니다. |
| 채팅 | 고객 메시지를 저장하고 설정된 말결 채팅 웹훅으로 전달합니다. 수탁사 테스트 계정 또는 서명된 콜백으로 답변을 남깁니다. |
| 전화 상담·녹취 | 설정된 말결 번호로 전화 연결하거나 콜백을 신청합니다. 녹취 사실을 안내하고 요청·동의를 기록합니다. 별도 수탁사 테스트 화면에서 **모의 오디오 파일** 등록·재생·보관기간 만료 파기를 시험합니다. 실제 전화선 녹음은 구현하지 않습니다. |
| 시세 화면 | 비로그인 방문자도 빗썸 공개 API 기반의 원화 마켓 현재가를 볼 수 있습니다. 비트코인 등 주요 종목을 선택하고 1분·30분·1시간·4시간·일·주·월 캔들 및 거래량, 호가, 최근 체결, 일별 시세를 확인합니다. 주문 기능은 없습니다. |
| 관리자 | 관리자 계정으로 마스킹된 회원 정보와 본인확인 상태, 상담 상태를 **읽기 전용**으로 봅니다. 회원번호·가입 신청번호·상담 접수번호로 검색할 수 있고, 조회와 마스킹 목록 다운로드를 기록합니다. 가입 신청은 본인확인 완료 후 회원 계정으로 전환되며, 가입 신청번호와 회원번호를 각각 조회할 수 있습니다. |

## 실행

Node.js 20 이상과 MySQL 8 서버가 필요합니다.

1. 새 데이터베이스라면 MySQL에서 `database.sql`을 실행합니다. 기존 RKX DB라면 적용 내역을 확인한 뒤 `migration-002.sql`부터 `migration-007.sql`까지 필요한 파일을 순서대로 실행합니다. 실행 전 DB를 백업하세요.
2. MySQL에 `rkx_consulting` 접근 권한을 가진 전용 사용자를 만듭니다.
3. `.env.example`을 `.env`로 복사해 DB 정보와 `APP_ORIGIN`을 설정합니다.
4. `npm install`, `npm start`를 실행하고 `http://localhost:3000`을 엽니다.
   개발 모드에서 같은 Wi-Fi의 다른 기기로 접속할 때는 Mac의 사설 IP와 포트 3000을 사용합니다. 서버는 현재 사설망 주소를 가입 요청의 허용 출처에 포함합니다. IP가 바뀌면 서버를 다시 실행하세요. 아이패드의 HTTP 접속에서는 브라우저 카메라 촬영이 제한될 수 있으므로 샘플 이미지 또는 파일 선택을 이용하거나 HTTPS를 설정하세요.
5. 관리자와 수탁사 테스트 계정은 각각 아래 스크립트로 생성합니다.

```bash
npm run admin:create -- admin@example.com 'LongPassword!A8' '관리자 이름'
npm run partner:create -- counselor@example.com 'LongPassword!A8' '말결 상담원'
```

명령줄에 비밀번호를 직접 입력하면 셸 기록에 남을 수 있습니다. 실제 운영 시 안전한 입력 절차를 사용하세요. 현재는 본인확인 미완료 고객도 로그인할 수 있으므로, 실제 본인확인 연동 시 기존 계정의 전환·이용 범위를 별도로 설계해야 합니다. 로컬 DB와 서버를 실행한 뒤 `node scripts/smoke-auth.js`로 가상 계정의 가입·로그인·상담 중복 접수 방지를 검사할 수 있습니다. 테스트 계정과 상담 건은 검사 후 삭제됩니다.

### 회원가입 내역 삭제

프로젝트 폴더에서 다음 명령을 실행합니다. 첫 명령은 삭제 대상 건수만 보여 주고, 두 번째 명령이 실제로 삭제합니다.

```bash
npm run accounts:clear
npm run accounts:clear -- --yes
```

이 명령은 RKX MySQL의 일반 회원 계정과 가입 신청을 모두 삭제합니다. 회원에 연결된 로그인 세션·상담·채팅·인증 기록은 외래 키에 따라 삭제되고, 해당 녹취 파일도 정리합니다. 관리자·수탁사 계정은 유지합니다. 삭제한 데이터는 복구할 수 없으므로 로컬 실습 DB에서만 사용하세요.

### 로그인 CAPTCHA 설정

[CERN captcha-api](https://github.com/CERN/captcha-api)의 `GET /api/v1.0/captcha`와 `POST /api/v1.0/captcha`를 RKX 서버가 중계합니다. Google 계정이나 reCAPTCHA 키는 필요하지 않습니다. `.env`의 `CERN_CAPTCHA_API_URL`에 API 기본 주소를 입력하세요. 로컬 실습에서는 `https://captcha.web.cern.ch/api/v1.0`을 사용할 수 있습니다. 실제 운영에서는 CERN 공개 서비스에 의존하지 않도록 해당 저장소를 별도 서버에 설치하고 자체 HTTPS 주소로 교체하세요. 자체 서버를 RKX와 같은 호스트에서 실행한다면 로컬 HTTP 주소도 허용됩니다.

로그인 실패가 2회 쌓이면 이미지 문자를 입력해야 비밀번호 검사를 계속합니다. 문자는 60초 동안 유효하며 한 번 검증하면 소진됩니다. 새 이미지 버튼과 음성 듣기를 제공합니다. CAPTCHA API 주소가 비어 있거나 연결되지 않으면 2회 실패 뒤 로그인은 차단됩니다. RKX는 CAPTCHA ID와 입력한 답만 서버에서 검증 서비스로 전달하며 이메일과 비밀번호는 전달하지 않습니다.

## 수탁사 연계 인터페이스

(주)인증정보평가(IJ-info)의 실습 API는 [저장소 README](https://github.com/ConsulT34M/IJ-info/blob/main/README.md)의 `DIRECT` 계약에 맞췄습니다. (주)말결(MK) 고객 채팅은 MK의 상담 접수·입장 코드·메시지 API를 사용합니다.

### RKX 화면과 IJ-info DIRECT 연동

가입 정보를 입력하고 **다음으로**를 누르면 PDF 흐름에 맞춘 2열 본인확인 화면이 열립니다. 왼쪽에서 이름·13자리 가상번호·연락처와 인증번호를 입력하고, 오른쪽 휴대전화 화면에서 문자 알림(수신함 링크), 신분증 확인, 셀카 촬영을 진행합니다. 웹캠의 **촬영하기** 또는 파일 선택으로 PNG/JPEG 이미지(최대 5MB)를 제출할 수 있습니다. 카메라는 `localhost` 또는 HTTPS에서만 사용할 수 있습니다. `public/identity.html`, `identity.css`, `identity.js`가 이 화면을 담당합니다.

샘플 인물은 [IJ-info의 `samples/people.json`](https://github.com/ConsulT34M/IJ-info/blob/main/samples/people.json)에 있는 10명입니다. 예를 들어 1번 장민지와 10번 박유진을 사용할 수 있고, 분실 상태인 9번은 인증할 수 없습니다. `public/assets/demo-id-card.svg`와 `demo-person.svg`는 실습용 합성 그림입니다. 샘플 증표/얼굴 사용 버튼으로 이미지를 선택할 수도 있습니다. **실제 주민등록증·실제 얼굴 사진을 입력하지 마세요.** RKX는 제출 이미지를 DB나 파일로 보관하지 않고 요청 처리 중 메모리에만 둡니다.

환경변수 3개(`IJINFO_BASE_URL`, `IJINFO_API_KEY`, `IJINFO_HMAC_SECRET`)가 모두 비어 있으면 로컬 모의 판정을 합니다. 설정하면 RKX 서버가 IJ-info의 `IA-01 DIRECT` → `IA-23 인증번호 발송` → `IA-24 인증번호 확인` → `IA-21 신분증` → `IA-22 얼굴` API를 HMAC 서명으로 호출합니다. `POST /api/identity/ijinfo-callback`은 서명된 `IA-11` 결과를 회원가입 건과 기존 회원 건 모두에 대해 받습니다. 가입 계정은 `IA-22` 성공 응답이 확인된 뒤에만 생성하고, 응답이 유실되면 `IA-12` 결과 조회로 확인합니다. IJ-info 앱과 PostgreSQL·모의 통신사 등은 별도 실행해야 합니다. 현재 IJ-info의 `FakeFaceMatcher`는 **이미지 내용이 아니라 파일명 힌트로 판정**하므로, 웹캠 사진도 실제 얼굴 일치를 증명하지 않습니다.

**휴대폰 본인확인은 IJ-info가 합니다.** RKX는 성명·연락처를 IJ-info에 넘기고(`IA-23`), IJ-info가 통신사에 명의를 확인한 뒤 인증번호를 **이용자 휴대폰으로** 보냅니다. 인증번호는 RKX 서버로 오지 않습니다 — 오른쪽 휴대전화 화면의 **문자 수신함 열기** 링크로 IJ-info 수신함에서 확인하고 왼쪽 화면에 입력합니다. 입력한 번호는 `IA-24`로 IJ-info가 검증하고, 통신사에서 받은 CI는 IJ-info 안에만 남습니다. **RKX는 CI를 만들지도 보지도 않습니다** — 예전처럼 같은 CI 키로 가상번호의 CI를 계산해 보내면 IJ-info의 X-01 대조(휴대폰 명의자 = 신분증 명의자)가 항등식이 되어 검사 구실을 하지 못하기 때문입니다. IJ-info 저장소에서 `flask create-client --name RKX --callback-url http://127.0.0.1:3000/api/identity/ijinfo-callback --allowed-ips 127.0.0.1`로 테스트 고객사를 만들고 발급된 API Key와 HMAC Secret을 RKX `.env`에 입력합니다. IJ-info 앱이 `http://127.0.0.1:8000`에서 동작하면 `IJINFO_BASE_URL`에 그 주소를 설정합니다. 운영 환경에서는 HTTPS만 허용됩니다.

기존 `POST /api/identity/callback`은 과거 가입 신청 자료를 처리하던 프로토타입 코드로 남아 있으며 새 흐름에서 호출되지 않습니다. 실제 운영 전에는 공식 휴대폰 확인, 실제 얼굴 판정, 수탁 계약과 보유·파기 정책을 별도로 완성해야 합니다.

웹 코드는 기능별 파일로 나눴습니다. `public/core.js`는 화면 이동·공통 API, `auth.js`는 회원가입·로그인, `consult.js`는 상담 접수, `chat.js`는 고객 채팅, `admin.js`와 `partner.js`는 권한별 화면, `market.js`는 시세, `captcha.js`는 로그인 CAPTCHA, `identity.js`·`identity.html`·`identity.css`는 본인확인 화면을 담당합니다. 서버의 본인확인 프로토콜은 `identity-service.js`와 `identity-routes.js`로 분리했습니다.

### 말결 상담 접수·채팅

오른쪽 아래 상담 버튼을 마우스로 가리키거나 누르면 세 채널이 열립니다. ‘AI 채팅 상담’의 대화는 MK 관리자 ‘AI → AI 채팅’에 저장됩니다. ‘상담원 채팅 문의’는 MK의 상담 운영 대기열로 연결됩니다. ‘전화 상담’은 고객이 마이크 사용을 허용하면 MK를 통해 브라우저에서 AI와 통화하며, 연결 기록은 ‘AI → AI 통화’에서 확인합니다. AI 사용 여부와 인사말은 MK의 ‘AI 설정’에서 관리합니다.

RKX의 채팅창과 MK 상담원 포털은 같은 WEB 상담방을 사용합니다. 기존 RKX DB에는 `migration-007.sql`을 적용하고, RKX 서버의 `.env`에 `MK_BASE_URL`과 `MK_PARTNER_TOKEN`을 설정합니다. 토큰 값은 MK 서버의 `PARTNER_TOKEN`과 같아야 합니다. 고객이 채팅창을 열면 MK 대기열에 접수되고, MK 상담원이 수락해 답하면 RKX에 표시됩니다. 종결된 방에서는 대화를 읽거나 ‘새 상담’을 시작할 수 있습니다.

로컬 MK의 기본 주소는 `https://127.0.0.1:8443`입니다. 자체 서명 인증서를 쓰면 MK Nginx의 공개 `cert.pem`을 RKX의 `.local/mk-tls/cert.pem`에 두고 `MK_CA_FILE=.local/mk-tls/cert.pem`을 설정합니다. RKX를 Docker Desktop에서 실행할 때는 `MK_DOCKER_BASE_URL=https://host.docker.internal:8443`을 사용합니다.

일반 상담·전화 접수는 `MK_WEBHOOK_URL`을 사용합니다. MK 방 연동을 설정하지 않은 설치에서는 기존 RKX 자체 채팅 및 `MK_CHAT_WEBHOOK_URL`을 사용합니다.

`MK_PHONE_NUMBER`를 설정하면 고객센터에 `tel:` 전화 연결 버튼이 표시됩니다. 미설정 시 화면의 `02-1234-5678`은 연결되지 않는 예시 번호이며, 콜백 신청만 이용할 수 있습니다.

### 모의 녹취

`RECORDING_RETENTION_DAYS`를 1~365의 정수로 설정해야 수탁사 테스트 화면에서 모의 오디오(최대 10MB)를 등록할 수 있습니다. 전화 상담이며 고객의 녹취 동의가 저장된 건만 등록할 수 있습니다. 파일은 `uploads/recordings/`에 저장되고, 보관기간이 끝나면 주기적으로 파기됩니다. 등록·재생·파기 이력이 MySQL에 남습니다. 실제 전화 상담 시스템/PBX와의 녹음 연결은 별도로 필요합니다.
