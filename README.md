# RKX 디지털 자산 컨설팅 웹앱

HTML·CSS·JavaScript, Node.js/Express, MySQL 8로 만든 로컬 실행 프로젝트입니다. 거래소형 시세 화면과 상담 연결을 제공하며, **매매·입출금·자산 수탁 기능은 없습니다.**

## 화면과 권한

| 기능 | 동작 |
| --- | --- |
| 회원가입·본인확인 | 약관, 개인정보 수집·이용, 처리위탁 고지에 동의해 신청합니다. IJINFO의 **서명된 완료 콜백을 받은 뒤에만** 고객 계정을 생성합니다. |
| 로그인·로그아웃 | 이메일(아이디)과 비밀번호를 서버에서 검증하고 HttpOnly 세션을 발급·종료합니다. 로그인 2회 실패 후부터 Google reCAPTCHA v2 확인이 필요하며, 비밀번호 오류 5회면 계정이 30분간 잠깁니다. |
| 상담 접수 | 고객이 문의 유형과 내용을 입력하면 접수번호를 만듭니다. 말결로 보내는 정보는 고객 식별키, 이름, 문의 유형·제목·내용, 접수번호이며 전화 콜백에는 연락처·희망 시간·녹취 동의 상태가 추가됩니다. |
| 채팅 | 고객 메시지를 저장하고 설정된 말결 채팅 웹훅으로 전달합니다. 수탁사 테스트 계정 또는 서명된 콜백으로 답변을 남깁니다. |
| 전화 상담·녹취 | 설정된 말결 번호로 전화 연결하거나 콜백을 신청합니다. 녹취 사실을 안내하고 요청·동의를 기록합니다. 별도 수탁사 테스트 화면에서 **모의 오디오 파일** 등록·재생·보관기간 만료 파기를 시험합니다. 실제 전화선 녹음은 구현하지 않습니다. |
| 시세 화면 | 비로그인 방문자도 빗썸 공개 API 기반의 원화 마켓 현재가를 볼 수 있습니다. 비트코인 등 주요 종목을 선택하고 1분·30분·1시간·4시간·일·주·월 캔들 및 거래량, 호가, 최근 체결, 일별 시세를 확인합니다. 주문 기능은 없습니다. |
| 관리자 | 관리자 계정으로 마스킹된 회원 정보, 가입 신청별 본인확인 결과, 상담 상태를 **읽기 전용**으로 봅니다. 조회와 마스킹 목록 다운로드를 기록합니다. |

## 실행

Node.js 20 이상과 MySQL 8 서버가 필요합니다.

1. 새 데이터베이스라면 MySQL에서 `database.sql`을 실행합니다. 이전 RKX 스키마에 데이터가 있다면 **한 번만** `migration-002.sql`을 실행합니다. 실행 전 DB를 백업하세요.
2. MySQL에 `rkx_consulting` 접근 권한을 가진 전용 사용자를 만듭니다.
3. `.env.example`을 `.env`로 복사해 DB 정보와 `APP_ORIGIN`을 설정합니다.
4. `npm install`, `npm start`를 실행하고 `http://localhost:3000`을 엽니다.
5. 관리자와 수탁사 테스트 계정은 각각 아래 스크립트로 생성합니다.

```bash
npm run admin:create -- admin@example.com '12자이상비밀번호' '관리자 이름'
npm run partner:create -- counselor@example.com '12자이상비밀번호' '말결 상담원'
```

명령줄에 비밀번호를 직접 입력하면 셸 기록에 남을 수 있습니다. 실제 운영 시 안전한 입력 절차를 사용하세요. 과거 스키마에서 만든 고객 계정은 본인확인 완료가 입증되지 않았으므로 로그인되지 않습니다. 기존 고객의 전환 방법은 실제 IJINFO 결과와 운영 정책에 맞게 별도로 설계해야 합니다.

### 로그인 CAPTCHA 설정

[Google reCAPTCHA 관리 콘솔](https://www.google.com/recaptcha/admin/create)에서 **v2 체크박스** 키를 발급하고 `.env`의 `RECAPTCHA_SITE_KEY`, `RECAPTCHA_SECRET_KEY`를 설정하세요. 로컬에서 시험할 때는 개발용 키의 허용 도메인에 `localhost`를 추가하고 `APP_ORIGIN`과 접속 주소를 일치시켜야 합니다. 두 키가 없으면 두 번 실패한 뒤 로그인은 차단되며 설정 안내가 표시됩니다. 브라우저 토큰은 서버에서 Google `siteverify` API로 검사하고, 응답의 호스트 이름이 `APP_ORIGIN`과 일치할 때만 인정합니다. 운영 키와 개발 키는 분리하세요.

## 수탁사 연계 인터페이스

첨부 자료를 기준으로 **(주)인증정보평가(IJINFO)**와 **(주)말결(MK)** 연결 지점을 마련했습니다. 실제 계약/API 명세가 없어 아래 요청·응답 형식은 **프로토타입 규격**입니다. 운영 전 수탁사 명세에 맞춰 수정해야 합니다.

### IJINFO 본인확인

`.env`의 `IJINFO_VERIFY_URL`, `IJINFO_API_KEY`, `IJINFO_CALLBACK_SECRET`이 모두 있어야 회원가입을 시작할 수 있습니다. 가입 신청 시 `{requestId, name, phone, callbackUrl}`을 보내고 `{verificationUrl, reference}`를 받는 형식을 가정합니다. 수탁사는 `POST /api/identity/callback`에 `{reference, status: "verified" | "rejected"}`를 보내며, JSON 원문에 대한 HMAC-SHA256을 `X-RKX-Signature` 헤더로 제공합니다. 완료 콜백 전에 계정은 생성되지 않습니다.

### 말결 상담 접수·채팅

`MK_WEBHOOK_URL`은 상담 접수, `MK_CHAT_WEBHOOK_URL`은 고객 채팅 메시지 전송에 사용합니다. 두 요청 모두 `MK_WEBHOOK_SECRET`으로 본문 HMAC-SHA256을 서명합니다. 말결의 상태 회신은 `POST /api/partner/status-callback`, 채팅 답변은 `POST /api/partner/chat-callback`으로 받습니다. 이 콜백에도 동일한 서명이 필요합니다.

연동 값이 없거나 전송에 실패해도 접수·채팅은 RKX DB에 저장되고 전송 상태가 남습니다. **실제 말결 시스템에는 전달되지 않습니다.** 수탁사 테스트 계정의 별도 화면에서 배정·답변 흐름을 시험할 수 있습니다. 운영 환경에서는 실패 건 재전송 큐, 중복 이벤트 처리, 수탁사와 합의한 상세 API가 더 필요합니다.

`MK_PHONE_NUMBER`를 설정하면 고객센터에 `tel:` 전화 연결 버튼이 표시됩니다. 미설정 시 화면의 `02-0000-0000`은 연결되지 않는 예시 번호이며, 콜백 신청만 이용할 수 있습니다.

### 모의 녹취

`RECORDING_RETENTION_DAYS`를 1~365의 정수로 설정해야 수탁사 테스트 화면에서 모의 오디오(최대 10MB)를 등록할 수 있습니다. 전화 상담이며 고객의 녹취 동의가 저장된 건만 등록할 수 있습니다. 파일은 `uploads/recordings/`에 저장되고, 보관기간이 끝나면 주기적으로 파기됩니다. 등록·재생·파기 이력이 MySQL에 남습니다. 실제 전화 상담 시스템/PBX와의 녹음 연결은 별도로 필요합니다.

## 운영 전 확인

- HTTPS, 실제 수탁사 계약·API 명세·전송 항목 확정
- 서비스 이용약관과 개인정보처리방침의 담당자, 보유기간, 위탁 범위, 시행일 확정
- 가입 신청 데이터 만료·파기 정책, 비밀번호 재설정, 영속적 요청 제한, 운영 로그 보존 정책
- 수탁사 전송 실패 재시도, 콜백 중복 처리, 녹취 보관 저장소·백업 정책
- 실제 가상자산 거래 기능을 추가할 경우 별도 규제·보안 검토

시세 API 참고: [빗썸 API 레퍼런스](https://apidocs.bithumb.com/reference/api-%EB%A0%88%ED%8D%BC%EB%9F%B0%EC%8A%A4). 서버에서 공개 마켓 목록·현재가·캔들·호가·체결 API를 호출하고 짧게 캐시합니다. API 오류 시 화면에 연결 지연 상태를 표시합니다. 정책 초안 참고: [개인정보보호위원회 처리방침 작성지침](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=12021).
